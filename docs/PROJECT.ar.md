# وثيقة مشروع Wumpa

محرّر PDF سريع، مجاني، يعمل دون اتصال، ومفتوح المصدر. يعمل على macOS وWindows وLinux، وكل المعالجة تجري على جهازك دون أن يغادر أي ملف.

هذه الوثيقة تشرح الهيكلة، ونموذج البناء، والمزايا، والتقنيات، والأسلوب الهندسي للمشروع. وهي مرجع للمطوّر الذي يريد فهم الشيفرة أو الإسهام فيها.

---

## 1. الفكرة والمبادئ

Wumpa مبني حول خمسة مبادئ ثابتة توجّه كل قرار في المشروع:

- **محلي بالكامل.** لا شبكة، لا تتبّع، لا حساب. الملفات لا تغادر الجهاز.
- **سريع وخفيف.** نواة Rust للعمليات الثقيلة، وواجهة ويب رشيقة. حجم المثبّت صغير (أقل من 5 ميغابايت على macOS).
- **PDF فقط.** النطاق محصور في ملفات PDF عمداً، دون أدوات أو وظائف خارج هذا النطاق.
- **تحرير غير مدمّر.** التعديلات تتراكم كحالة في الذاكرة، والملف الأصلي لا يُلمس إلا عند الحفظ الصريح.
- **ثنائي اللغة من الأساس.** عربي/إنجليزي مع دعم كامل للاتجاه من اليمين لليسار (RTL)، وكشف لغة تلقائي لكل مستند.

## 2. التقنيات

| الطبقة | التقنية | الدور |
|---|---|---|
| الإطار | **Tauri v2** | غلاف سطح المكتب: نافذة نظام أصلية + WebView، وجسر IPC بين الواجهة والنواة |
| النواة | **Rust** | كل عمليات PDF الثقيلة (قراءة، بناء، دمج، تقسيم، ضغط، تعليقات) |
| مكتبة PDF | **lopdf 0.45** | قراءة بنية PDF وتعديلها على مستوى الكائنات |
| الوسائط | **image 0.25** (jpeg + png) | ضغط الصور وإعادة تحجيمها داخل المستند |
| الضغط | **flate2** | ضغط مجاري المحتوى (Flate/zlib) |
| الترميز | **base64**, **getrandom** | نقل الصور بين الواجهة والنواة، وتوليد المعرّفات والمفاتيح |
| التجزئة | **sha2** | بصمة الملف لسجل محاولات كلمة المرور |
| الواجهة | **React 19 + TypeScript 6** | واجهة المستخدم |
| الحالة | **zustand 5** | مخزن حالة مركزي خفيف |
| العرض | **PDF.js v6** (pdfjs-dist) | رسم الصفحات على Canvas واستخراج النص والتعليقات والروابط |
| QR | **jsqr** | قراءة رموز QR من الصفحات |
| البناء | **Vite 8** | خادم تطوير مع HMR، وتجميع الإنتاج |

**أحجام الشيفرة تقريباً:** الواجهة ~7080 سطراً (TypeScript/TSX)، والنواة ~3143 سطراً (Rust)، والتنسيق ~2140 سطراً (CSS).

## 3. الهيكلة المعمارية

### 3.1 نموذج العمليتين

يعمل التطبيق كعمليتين تتواصلان عبر جسر Tauri (IPC):

```
┌─────────────────────────────┐        ┌──────────────────────────────┐
│  الواجهة (WebView)           │        │  النواة (Rust)                │
│  React + TypeScript          │        │  lopdf + image + flate2       │
│                              │        │                               │
│  • عرض الصفحات (PDF.js)      │        │  • قراءة/بناء/حفظ PDF          │
│  • الحالة والتفاعل (zustand) │ ◀────▶ │  • دمج/تقسيم/ضغط               │
│  • الطبقات فوق الصفحة        │  IPC   │  • التعليقات والأختام          │
│  • i18n و RTL والثيمات       │invoke()│  • تحرير الكائنات              │
└─────────────────────────────┘        └──────────────────────────────┘
        العرض والتفاعل                         كل ما يكتب إلى القرص
```

قاعدة التقسيم بسيطة: **الواجهة تعرض وتجمع نوايا المستخدم، والنواة تنفّذ كل ما يمسّ بنية PDF أو يكتب إلى القرص.** العرض على الشاشة يتم عبر PDF.js في الواجهة؛ أما الكتابة النهائية للملف فتتم دائماً في Rust.

### 3.5 نموذج الحالة

كل مستند مفتوح هو `Tab`. التعديلات لا تُكتب للقرص؛ تعيش هنا حتى الحفظ:

```ts
interface Tab {
  id; path; name;
  pages: PageSpec[];          // ترتيب الصفحات ودورانها (src=0 يعني صفحة فارغة)
  highlights; notes;          // التظليل والملاحظات اللاصقة
  edits: ObjectEdit[];        // نقل/تحجيم/حذف كائنات
  stamps; shapes;             // الأختام/التواقيع، والرسم
  bookmarks: Bookmark[]|null; // null = لم تُمسّ، يُبقى فهرس الملف كما هو
  links; linkRemovals;        // روابط مضافة وأخرى محذوفة
  signatures?;                // نتيجة التحقق من تواقيع الملف على القرص
  past: Snapshot[];           // مكدّس التراجع
  future: Snapshot[];         // مكدّس الإعادة
  zoom; currentPage; selected;
  dirty;                      // هل توجد تغييرات غير محفوظة
  docVersion;                 // يتغيّر عند تغيّر الملف على القرص (بعد الحفظ)
  detectedLang?;              // لغة مكتشفة لتوجيه RTL
}
```

الصفحات الفارغة المدرجة تحمل `src` سالباً فريداً فتبقى تعليقاتها معها عند الحفظ. `Snapshot` هو الجزء القابل للتراجع من `Tab` (الصفحات والتعليقات والإشارات والروابط). التراجع والإعادة مجرّد نقل بين `past` و`future`.

## 4. دورة حياة المستند

هذه الدورة هي أوضح شرح لكيفية تعاون الأجزاء:

**1) الفتح.** `actions.openPaths` يطلب `load_pdf` فيعيد البايتات، ثم `pdf.ts` ينشئ مستند PDF.js ويحسب أبعاد كل صفحة ويقرأ الأذونات. تُحمّل الإشارات لاحقاً بشكل غير متزامن.

**2) التحرير غير المدمّر.** كل فعل (تدوير، تظليل، ملاحظة، رسم، ختم، إضافة رابط...) يعدّل حالة `Tab` عبر `mutateDoc`، الذي يلتقط لقطة للتراجع أولاً. **الملف على القرص لا يُلمس إطلاقاً** في هذه المرحلة.

**3) العرض والطبقات.** `Viewer` يرسم كل صفحة على Canvas عبر PDF.js عند اقترابها من الشاشة، ويبني طبقة النص بعد هدوء التمرير، ويكشف رموز QR في Worker منفصل. عند الفتح تُقاس أبعاد أول 40 صفحة فقط والباقي في الخلفية. ثم يركّب فوق الصفحة طبقات مطلقة الموضع: التظليل، الملاحظات، الأختام، الأشكال، الروابط، وطبقة النص القابلة للتحديد. كل طبقة تحوّل إحداثيات PDF إلى إحداثيات الشاشة عبر `viewport` من PDF.js، فتبقى محاذاة مع الزوم والدوران.

**4) الحفظ وإعادة البناء.** عند الحفظ، `actions.saveActive` يرسل ترتيب الصفحات وكل التعليقات والإضافات إلى `save_document`. في النواة يستدعي `pdf_ops::rebuild_with()` الذي: يطبّق الروابط، ثم الإشارات، ثم الأختام وتعديلات الكائنات، ثم يشذّب الكائنات غير المستخدمة، ثم يكتب الملف. بعدها تُصفّر حالة التحرير ويرتفع `docVersion` فيعيد PDF.js تحميل الملف المحفوظ.

**5) التراجع/الإعادة.** بما أن كل تعديل ملتقَط كلقطة، فالتراجع نقل لقطة من `past` إلى `future` واستعادتها، دون أي مسّ للقرص.

## 5. المزايا

**العرض والتنقّل**
- فتح عدة ملفات في تبويبات، والسحب والإفلات للفتح
- تمرير سلس، تكبير/تصغير، ملاءمة العرض، مصغّرات الصفحات
- تحديد ونسخ النص، والبحث داخل المستند
- فتح الملفات المحمية بكلمة مرور للعرض

**تنظيم الصفحات**
- دمج عدة ملفات، تقسيم إلى أجزاء، استخراج صفحات
- إعادة ترتيب بالسحب، حذف، تدوير
- إدراج صفحات فارغة، تكرار صفحة، تصدير صفحة كـ PNG

**التعليق والمراجعة**
- تظليل النص وإضافة ملاحظات لاصقة (تُحفظ كتعليقات PDF حقيقية)
- عرض التظليل والملاحظات الموجودة مسبقاً في الملف
- الرسم على الصفحات: حبر حرّ، مستطيل، بيضاوي، خط، سهم بستة ألوان
- الأختام النصية والتوقيع المرسوم باليد (بأسلوب Fill & Sign)
- مقارنة الملفات بأسلوب Acrobat: نافذة «الملف القديم/الملف الجديد»، صفحة ملخّص بعدد التغييرات (استبدال/إضافة/حذف)، عرض جنباً إلى جنب أو ملفاً واحداً أو تراكباً، تمييز الأسطر، وملاحظة منبثقة لكل تغيير مع التنقّل بين التغييرات

**تحرير المحتوى**
- محرّر الكائنات: نقل أو تحجيم أو حذف فعلي لأي نص أو صورة أو شكل
- حذف كل ما داخل مستطيل تحدّده
- تحرير النص في مكانه بالنقر المزدوج
- إضافة نص حرّ بأي لغة (يرسمه النظام، فالتشكيل العربي صحيح)

**التنظيم والربط**
- الإشارات (الفهرس): إضافة، إعادة تسمية، توجيه، تداخل، إعادة ترتيب، حذف — تُحفظ كشجرة `/Outlines` حقيقية
- الروابط التفاعلية: رسم منطقة رابط تشير إلى عنوان ويب أو صفحة، واتباع الروابط الموجودة وحذفها

**الحماية**
- حماية بكلمة مرور للفتح وكلمة مرور للأذونات (طباعة، نسخ، تحرير، تعليق) بتشفير AES-256
- إزالة الحماية بكلمة مرور الأذونات، وشارة في شريط الحالة للملفات المحمية
- حماية من التخمين داخل التطبيق: مقياس قوة كلمة المرور واقتراح كلمة قوية، وقفل تصاعدي بعد المحاولات الخاطئة (يُحفظ في سجل محلي مرتبط ببصمة الملف)، وسياسة اختيارية مضمّنة في الملف تُتلف النسخة المحلية بعد عدد محدد من المحاولات الخاطئة. ملف PDF لا يستطيع منع التخمين بأدوات أخرى، فالحماية الحقيقية هي طول كلمة المرور

**صورة إلى PDF (الصفحات الممسوحة)**
- يكتشف الصفحات التي محتواها صورة واحدة فقط، ويعيد بناءها نصاً حقيقياً قابلاً للتحديد والبحث، مع الجداول وحدودها والصور المضمّنة، في نسخة جديدة من الملف
- التعرّف على النص يعمل على الجهاز بالكامل عبر محرّك النظام (Apple Vision على macOS، بالعربية والإنجليزية وغيرها) من خلال أداة مساعدة `tools/ocr` تُبنى مع التطبيق؛ Windows وLinux لاحقاً
- التحليل في النواة: تقويم الميل، استخراج الخطوط والجداول والصور، تجميع السطور إلى فقرات مع المحاذاة والاتجاه وحجم الخط والسُّمك، ثم تركيب الصفحة بخطوط Noto مضمّنة مع تشكيل عربي صحيح (rustybuzz) وجدول ToUnicode للنسخ والبحث
- دقة الموضع: كل سطر كتلة مستقلة يُثبَّت نصها على حبر المسح نفسه (الحجم من ارتفاع الحروف، والموضع من أول صف محبّر)، والفقرة تحدد المحاذاة فقط (ضبط الأسطر عدا الأخير، وتوسيط، ويمين/يسار)؛ الحقول المجاورة للعناوين في النماذج تبقى في مواضعها
- المتانة على المسح الحقيقي: المناطق الكثيفة الحبر (صور، أختام، شعارات) تُستثنى من كشف الخطوط والجداول ويُحتفظ بها صورة كاملة بما فيها نصها؛ الخطوط المكرّرة من المسح تُدمج؛ والخلايا المحبّرة التي فاتها التعرّف (كالأرقام المفردة) تُعاد قراءتها على قصاصة الصف ثم العمود ثم الخلية بوضع بلا تصحيح لغوي؛ والخلية التي تحوي ثلاثة أسطر فأكثر تُعامل إطاراً لنص حر

**تصدير إلى Word وExcel**
- الصفحات النصية تُقرأ حرفاً حرفاً من الملف نفسه (`export/glyphs.rs`: مسار المحتوى، المصفوفات، عروض الحروف، خرائط ToUnicode والترميزات البسيطة، النماذج المضمّنة، اسم الخط ووزنه)، فتبقى الحروف المركّبة مثل «لا» سليمة ويُعاد السطر العربي إلى ترتيبه المنطقي من مواضع الحروف (الأرقام والكلمات اللاتينية تحتفظ باتجاهها، الأقواس تُعكس للصواب، العلامات تلتصق بحروفها)؛ وعند تعذّر قراءة خط ما تُؤخذ قراءة pdf.js للسطر نفسه. تُرسم الصفحة صورة نقطية تمر على محلّل المسح نفسه لاستخراج الخطوط والجداول والصور، وتُضاف الصور والرسوم المتجهة المذكورة في الملف (دون خلفيات النص وإطاراته)؛ الصفحات الممسوحة تمر على التعرّف الضوئي
- خوارزمية التخطيط المشتركة: الجداول ذات الحدود من تقاطع الخطوط، والجداول بلا حدود من اصطفاف الكلمات في أعمدة تفصلها فجوات صافية على طول الكتلة (الصفحة متعددة الأعمدة تُقطع عند فواصلها أولاً، أعمدة النثر لا تُعدّ جدولاً، الصفوف تُجمّع بمراكز السطور وتُطوى الأسطر الثانية للعناوين والخلايا في صفوفها، وتُستبعد العناوين العابرة والأسطر الطرفية ذات العمود الواحد)، والفقرات من تجميع السطور، وترتيب القراءة بالقطع المتكرر على أوسع فراغ أفقي أو عمودي (الأعمدة من اليمين في الصفحات العربية، مع نطاق علوي وسفلي يُقرأ قبل الأعمدة وبعدها، وقشر الكتلة العليا حين لا يوجد قطع)
- Word: حجم الصفحة وهوامشها من المستند، قسم لكل صفحة، الفقرات بمحاذاتها واتجاهها وحجمها وسُمكها ولونها، الأسطر الملتفة تنساب والأسطر المقصودة (عناوين، حقول «العنوان:») تحتفظ بكسرها، الجداول بأعمدتها الحقيقية ودمج الخلايا وحدودها (وبترتيب بصري من اليمين للجداول العربية)، والصور مضمّنة بحجمها
- Excel: ورقة «صفحة N» لكل صفحة تعيد الصفحة كما هي على شبكة خطوطها من حواف الفقرات والجداول والصور (عرض الأعمدة وارتفاع الصفوف بالنقاط)، كل فقرة في خلاياها المدمجة بحجم خطها ومحاذاتها واتجاهها، وخلايا الجداول في مواضعها بحدودها، والصور مثبّتة بإحداثياتها كرسوم؛ ثم ورقة بيانات نظيفة لكل جدول («صفحة N - جدول M») بأرقام حقيقية بتنسيقها (فواصل الآلاف، الكسور، النسب المئوية، الأرقام العربية الهندية، السالب بين قوسين) ما دام العمود رقمياً، ودمج وعرض أعمدة واتجاه الورقة
- الملفان يُكتبان مباشرة بصيغة Office Open XML داخل حاوية zip، بلا مكتبات خارجية؛ الصور الفوتوغرافية الكبيرة تُضمَّن JPEG والرسوم والأختام تبقى PNG بلا فقد (والقاعدة نفسها في مركّب PDF)
- **اختبارات مرجعية** (`src-tauri/testdata/export/` و`export/regression.rs`): خمسة مستندات حقيقية (تقرير عربي، مقال بعمودين، فاتورة إنجليزية، فاتورة عربية مُعاد بناؤها، خطاب) مع صورة صفحتها الأولى، وما يجب أن يخرج منها (الجداول وأبعادها، فقرات وخلايا بعينها، وأخطاء سابقة يجب ألا تعود)؛ تعمل ضمن `cargo test`
- **اختبار داخل التطبيق الحقيقي** (`tools/autotest.sh`): يبني نسخة تطوير ويشغّلها مع `WUMPA_AUTOTEST_SRC`/`WUMPA_AUTOTEST_OUT` فتفتح الملف وتقرأ نصه وتصدّره Word وExcel وتكتب الحكم في سجل التطبيق ثم تُغلق؛ يكشف ما لا تصل إليه اختبارات الوحدات (محرّك WebKit، قناة IPC)، ويعمل في `.github/workflows/test.yml` مع بقية الفحوص

**الأدوات**
- ضغط الملف مع التحكم بالجودة والأبعاد
- إنشاء PDF جديد، إدراج صور وجداول
- قراءة رموز QR من الصفحات، وتوليدها

**التجربة**

## 6. طريقة البناء والتشغيل

### المتطلبات
- [Rust](https://rustup.rs) (عبر rustup)
- Node.js 20+

### التطوير
```sh
npm install
npm run tauri dev    # تشغيل تطبيق سطح المكتب مع إعادة تحميل حيّة
npm run dev          # الواجهة فقط في المتصفح (لتجربة سريعة للتصميم)
```
خادم Vite يعمل على المنفذ الثابت 1420.

### الفحص والاختبارات
```sh
npx tsc --noEmit                 # فحص أنواع الواجهة
cd src-tauri && cargo test       # اختبارات النواة (68 اختباراً)
npm run lint                     # ESLint
npm run format                   # Prettier
npm test                         # اختبارات الواجهة (Vitest)
```

### بناء المثبّتات
```sh
npm run tauri build
```
المخرجات: `.app`/`.dmg` على macOS، و`.exe`/`.msi` على Windows، و`.AppImage`/`.deb` على Linux.

### الإصدار عبر GitHub Actions
ملف `.github/workflows/release.yml` يُشغَّل عند دفع وسم بصيغة `v*` (أو يدوياً). يبني على ثلاث منصّات بالتوازي:

| المنصّة | الهدف |
|---|---|
| macOS | `universal-apple-darwin` (Intel + Apple Silicon) |
| Windows | الهدف الافتراضي |
| Ubuntu 22.04 | Linux |

يستخدم `tauri-action` لإنتاج مسوّدة إصدار (draft release) مرفقة بكل المثبّتات. إعداد الحزمة في `tauri.conf.json`: اسم المنتج Wumpa، المعرّف `com.wumpa.app`، نافذة 1280×820 بحد أدنى 900×600، وربط ملفات PDF بدور «محرّر» ليفتحها النقر المزدوج.

## 7. الأسلوب الهندسي

- **تعليقات قليلة بأسلوب بشري هندسي.** الشيفرة تشرح نفسها بأسماء واضحة؛ التعليق يُحجز للنيّة غير الظاهرة، لا لإعادة سرد ما تفعله السطور.
- **انضباط النطاق.** PDF فقط. أي ميزة خارج هذا النطاق تُرفض مهما كانت مفيدة.
- **حدود واضحة بين الطبقات.** الواجهة لا تكتب للقرص أبداً؛ النواة لا تعرف شيئاً عن React. الجسر الوحيد هو أوامر IPC في `backend.ts` و`lib.rs`.
- **حالة غير قابلة للتغيير في مكانها.** كل تعديل ينتج حالة جديدة عبر zustand، ما يجعل التراجع/الإعادة مجرّد تبديل لقطات.
- **حفظ بإعادة البناء.** بدل الترقيع المتزايد للملف، يُعاد بناء المستند من المصدر + النوايا عند كل حفظ، فتبقى النتيجة نظيفة ومتوقَّعة.
- **تصميم موحّد عبر متغيّرات CSS.** الثيمات (فاتح/داكن) وRTL كلها عبر متغيّرات في `styles/base.css`، والتنسيق مقسّم ملفاً لكل قسم يستوردها `styles/index.css` بالترتيب.
- **إبلاغ أخطاء للمستخدم لا تعطّل.** الأخطاء من النواة تُلتقط وتُعرض في شريط الحالة بلغة المستخدم عبر `errors.ts`.

## 8. الأمان والخصوصية

- **لا شبكة ولا تتبّع.** لا يُجرى أي اتصال خارجي. الملفات تبقى على الجهاز.
- **CSP مُدار.** الواجهة محليّة بالكامل، دون موارد خارجية.
- **حماية مشروعة فقط.** ميزة الحماية بكلمة المرور تدعم: ضبط كلمة مرور للملف، وإزالة كلمة مرور **يعرفها المستخدم ويزوّدنا بها**، وقراءة الأذونات. لا يوجد ولن يوجد مفتاح رئيسي أو باب خلفي لفتح ملفات مقفلة لا يملك المستخدم كلمتها.
